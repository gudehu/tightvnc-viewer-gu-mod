# tightVNC-gu mod

基于 [TightVNC 2.8.90](https://www.tightvnc.com/) GPL 源码构建的 Windows 远程查看器（Viewer）增强分支。在原生远程桌面查看能力之上，扩展了双向文件传输、远程程序启动、会话只读控制与输入体验优化等功能。

| 项目 | 说明 |
| --- | --- |
| 许可证 | [GNU GPL v2](LICENSE)（与上游一致） |
| 支持平台 | Windows 10 / 11 x64 |
| 组件范围 | 仅 Viewer（查看端）；Server（被控端）沿用标准 TightVNC Server |
| 上游版本 | TightVNC 2.8.90 GPL 分支 |
| 修改标识 | 源码中以 `HU patch` 注释标注，清单见 [CHANGES.md](CHANGES.md) |

> 本项目为 TightVNC 的**修改版**，非官方发布。仓库同时提供完整对应源码与编译产物，符合 GPL v2 的分发要求；合规细节见 [COMPLIANCE.md](COMPLIANCE.md)。

## 1. 项目概述

TightVNC 2.x 是遵循 GNU GPL v2 的开源分支，4.x 为闭源商业分支，二者互不兼容。本项目基于 2.8.90 的 GPL 源码，仅对**查看端**进行增强，被控端无需更换或重启，使用任意标准 TightVNC Server 即可。

术语约定：

- **本地 / 查看端（Viewer）**：运行本程序、发起控制的一端。
- **远端 / 被控端（Server）**：被访问和控制的一端。
- **RFB**：Remote Framebuffer 协议，VNC 的底层通信协议。

## 2. 快速开始

### 2.1 运行

直接执行 `bin\tvnviewer.exe`，按原版 TightVNC 的方式输入地址与密码建立连接。亦可使用命令行参数：

```
tvnviewer.exe 199.199.12.178:5900 -password=<密码>
```

连接建立后，所有增强功能自动可用，无需额外配置。若需从源码构建，见第 7 节。

### 2.2 前置条件

- 远端运行标准 TightVNC Server，并启用**文件传输**功能（文件传输相关功能依赖此项）。
- 建议开启**剪贴板同步**（默认开启）：文件获取与远程命令下发依赖该项能力。

## 3. 功能总览

原生工具栏保留 16 个按钮（连接、缩放、全屏、发送 Ctrl+Alt+Del 等官方功能）。本分支在其后**追加 12 个按钮**，分为两组：

| 分组 | 按钮 | 用途 |
| --- | --- | --- |
| 文件传输与程序启动 | 发送文件、获取文件、get目录、send目录、本地cmd、远程cmd、本地txt、远程txt | 双向传文件、快速打开本地/远端目录与程序 |
| 会话控制增强 | 仅查看、Candy热键、滚动到顶、远端桌面 | 只读切换、快捷键注入、视图定位与桌面切换 |

此外还有两项不占用按钮的增强：**边缘自动滚动**与**中文输入隔离**，见第 5 节。

---

## 4. 按钮功能详解

### 4.1 文件传输与程序启动

#### 1. 发送文件

- **功能**：将本地一个或多个文件/文件夹上传至远端。
- **操作**：点击按钮后在弹出的多选对话框中选择目标；或直接从资源管理器将文件拖放到远程画面窗口。
- **实现**：通过 `GetOpenFileNameW` 获取多选路径，交由 `HuTransfer` 模块调用 TightVNC 的 RFB 文件传输扩展上传至远端 `C:\HU-vnc-send`。目标目录不存在时自动创建。传输过程由独立非模态进度窗口呈现，不阻塞远程会话。

#### 2. 获取文件

- **功能**：将远端文件下载至本地。
- **操作**：在远端资源管理器中选中文件，执行"复制文件地址"（`Shift+右键`，Windows 11 可用 `Ctrl+Shift+C`）；返回查看器点击本按钮，或按 `Ctrl+Alt+G`。文件保存至本地 `C:\HU-vnc-get`。
- **实现**：RFB 协议不提供"远端选中项"信息，因此以剪贴板作为路径载体：远端复制的完整路径经剪贴板同步传回本地，程序解析路径后经文件传输通道下载。剪贴板无有效路径时，进度窗口会给出操作提示。

#### 3. get目录

- **功能**：在本地资源管理器中打开 `C:\HU-vnc-get`。
- **操作**：点击即可；目录不存在时自动创建。
- **实现**：本地 `CreateDirectoryW` + `ShellExecuteW`，不涉及网络通信。

#### 4. send目录

- **功能**：在远端打开 `C:\HU-vnc-send`。
- **操作**：点击即可。
- **实现**：通过远端 `Win+R` 调出"运行"对话框，写入路径并回车。运行对话框可直接打开文件夹路径，故无需 `explorer` 命令前缀——远端服务端会丢弃空格键的 keysym，命令中应避免出现空格。

#### 5. 本地cmd

- **功能**：在本地启动命令提示符。
- **操作**：点击即可。
- **实现**：本地 `ShellExecuteW("cmd.exe")`。置于工具栏便于与"远程cmd"对照使用。

#### 6. 远程cmd

- **功能**：在远端启动命令提示符。
- **操作**：点击即可。
- **实现**：远端 `Win+R` 调出"运行"对话框后，通过 RFB `ClientCutText` 将命令文本写入远端剪贴板，再发送 `Ctrl+V` 与回车。相比逐字符输入，该方式可规避慢速主机丢失按键或中文输入法吞掉字母键导致运行框残留旧命令的问题；代码中添加了多轮修饰键释放与等待，确保对话框就绪。

#### 7. 本地txt

- **功能**：在本地启动记事本。
- **操作**：点击即可。
- **实现**：本地 `ShellExecuteW("notepad.exe")`。

#### 8. 远程txt

- **功能**：在远端启动记事本。
- **操作**：点击即可。
- **实现**：与"远程cmd"相同的 `Win+R` + 剪贴板粘贴机制，下发命令为 `notepad`。

> 文件传输过程中出现同名目标时，进度窗口提供四种处理策略：覆盖、跳过、自动重命名（附加日期）和取消传输；并支持"后续同名项按此处理"的批量策略。传输日志按日期写入本地 `C:\HU-vnc-get`，采用 UTF-8 编码。

### 4.2 会话控制增强

#### 9. 仅查看

- **功能**：切换只读（view-only）会话。启用后本地键鼠输入不再转发至远端，画面正常显示；再次点击恢复控制。
- **操作**：点击按钮，或使用热键 `Ctrl+Shift+O`。启用时按钮呈按下状态，悬停提示中标注热键。
- **实现**：切换连接配置中的 view-only 标志。`DesktopWindow` 在处理每个输入事件前检查该标志，只读状态下直接丢弃事件。同时自动禁用所有会操作远端的按钮。热键通过 `RegisterHotKey(MOD_CONTROL|MOD_SHIFT, 'O')` 注册为系统级热键，窗口模式与全屏模式均有效；弃用早期 `Alt+O` 方案的原因是其易被 Windows 系统菜单拦截。

#### 10. Candy热键

- **功能**：向远端发送 `Ctrl+F8`（Candy 类应用使用的快捷键）。
- **操作**：建立连接后点击；未连接时按钮禁用。
- **实现**：以 RFB keysym 依次发送 Ctrl 按下、F8 按下/松开、Ctrl 松开。按键直接注入远端，不受本地键盘状态影响。

#### 11. 滚动到顶

- **功能**：将远程画面直接定位到垂直顶部（位置 0）。
- **操作**：随时点击。
- **实现**：调用 `DesktopWindow::scrollToTop()` 将垂直滚动位置设为 0。由于边缘自动滚动在接近顶部时预留 10 像素保护带（见 5.1），此按钮提供到达真实顶部的显式途径。

#### 12. 远端桌面

- **功能**：切换远端的"显示桌面"状态。点击一次最小化全部窗口并显示桌面，再次点击恢复。
- **操作**：建立连接且非只读状态下点击。
- **实现**：向远端发送 `Win+D` 组合键。采用与"远程cmd"一致的底层 keysym 发送路径（`XK_Super_L` + `XK_d`），并在发送后执行修饰键状态清扫，避免修饰键卡滞。早期使用虚拟键码发送导致 D 键丢失、仅弹出开始菜单，现已修正并完成真机验证。

## 5. 输入与视图增强

### 5.1 边缘自动滚动

鼠标移至远程画面的上下左右边缘时自动滚动画面，触发边距更大、滚动速度更快。鼠标移出窗口边框后，只要该方向仍有未显示区域，滚动持续进行，直至内容尽头停止。向上滚动在距远端顶部 10 像素处停止，以避免鼠标触及屏幕顶端时误触发远端停靠在顶部的程序。

### 5.2 中文输入隔离

原版及部分衍生版本在远端使用输入法时，本地输入法会同步弹出候选框并产生跳动（字符不会真正上屏）。本分支在远程画面窗口创建时解除其输入上下文关联（`ImmAssociateContext(hwnd, NULL)`），使本地输入法不再响应该窗口的键盘消息，候选框仅在远端显示。

## 6. 快捷键

| 快捷键 | 功能 | 生效范围 |
| --- | --- | --- |
| `Ctrl+Shift+O` | 切换只读会话 | 查看器窗口持有焦点时（窗口/全屏模式均可） |
| `Ctrl+Alt+G` | 获取剪贴板中路径对应的远端文件 | 查看器窗口持有焦点时；全屏模式下键盘钩子行为更稳定，亦可直接点击"获取文件"按钮 |
| `Ctrl+F8` | 由 Candy热键按钮注入远端 | 需点击按钮触发，非本地快捷键 |

## 7. 从源码构建

**环境要求**

- Visual Studio 2022（"使用 C++ 的桌面开发"工作负载）
- Windows 10 SDK（10.0.22621.0 或兼容版本）
- v143 工具集

**构建命令**

```
python tools/build.py
```

脚本自动定位 MSBuild.exe。若无法定位，可通过环境变量 `VS_MSBUILD` 指定其完整路径。产物位于 `src/Release/x64/tvnviewer.exe`。

## 8. 注意事项

1. **服务端配置**：文件传输功能依赖远端 TightVNC Server 开启对应选项；未开启时进度窗口会报告具体错误。
2. **剪贴板安全**：剪贴板同步会将本地剪贴板内容传递给远端，不应在不受信任的会话中保留敏感信息。
3. **部署范围**：本修改仅涉及查看端，被控端无需更换或重启。
4. **传输规模**：单次建议不超过数百个文件；大文件传输耗时取决于网络与磁盘性能，以进度窗口结果为准。
5. **安全软件误报**：因包含远程控制与键盘钩子能力，部分安全软件可能误报。建议核对源码后自行编译，或仅从可信来源获取。
6. **法律风险**：远程控制工具可能被滥用。请仅在自身拥有或已获授权的设备上使用，并遵守所在地区的法律法规。
